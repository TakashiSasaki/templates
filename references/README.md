# Operational references

Place documents here only when an agent may need them while performing the skill.

Examples:

- input and output contracts;
- domain terminology;
- compatibility policies;
- error-code reference;
- bounded troubleshooting procedures.

`SKILL.md` must say when each reference should be read. Avoid deep chains where one reference points to another reference that points to a third.

Maintainer-only architecture and release material belongs under `docs/`, not here.
